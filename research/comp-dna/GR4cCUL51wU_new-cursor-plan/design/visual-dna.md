## Archetype
"Talking-head take + tweet/screenshot proof-card inserts" — a single continuous handheld/tripod monologue (no hard cuts) intercut with static overlay cards (tweets, product UI screenshots, data maps) that pop in over the host's chest/lower frame to back up each claim.

## Hook mechanic (first 3s)
Cold open mid-sentence over the host's OWN tweet screenshot ("tweet is going... because I...") — no title card, no "let me tell you," just drops viewer into an already-unfolding controversy. The tweet-as-hook implies external validation/drama (people are already reacting) before host has said anything substantive.

## Caption grammar
Burned-in yellow bold captions, 1-3 words per card, changing almost every second (word/phrase-paced to speech, not full sentences at once). Sentence case, no ALL CAPS. Positioned lower-third, centered, single line — never obstructs overlay cards which sit mid-frame. High-contrast black stroke/shadow implied for legibility over both wall and screen backgrounds.

## Information density
Very high relative to a "vlog" style — screenshot/proof card on screen for roughly 40-50% of the runtime (tweets, product UI, choropleth maps). Host body alternates profile-facing (pacing/thinking beats) vs frontal (assertion/punchline beats) to keep a single unbroken take visually varied without cutting.

## Reusable asset components
- **Tweet-card overlay**: white rounded card, avatar+handle+timestamp header, tweet body text, engagement icon row (reply/retweet/like/share) at bottom — the single most-reused asset type (appears ~6 times)
- **Product UI screenshot card**: cropped screenshot of a real app UI (Cursor pricing card, model picker dropdown) framed in a white card, used as "hard proof" of the claim being made
- **Choropleth/data-map card**: world map with one country highlighted red + inset stat box (%, year, trend arrow) — used as rebuttal/data-authority asset
- **Full-bleed screen-share**: host's own monitor showing a code editor in the background (environment prop, not a discrete overlay, but reinforces "credible builder" status)

## Colors → content mapping notes
- Neutral off-white/grey studio + black wardrobe = zero color noise from the host himself, so all color signal comes from overlay cards
- Overlay cards are native-app screenshots (white/blue/black — Twitter/X + Cursor's own UI), not custom-designed — authenticity over polish
- Caption yellow is the only "branded" color choice, a generic high-contrast YouTube convention rather than a channel-specific brand color
- Red is reserved exclusively for the data-map highlight color (danger/poverty signal), never used elsewhere — disciplined single-purpose color use

## Weaknesses / what NOT to copy
- Zero on-screen title/thesis card at t=0 — relies entirely on caption text to convey the tweet's content; a viewer who can't read fast/has captions off loses the hook
- No lower-third name/handle ID for the host — pure personality-brand play, doesn't work for a synthetic/rotating host identity
- Overlay cards are raw unstyled screenshots (default Twitter/X card chrome) — fine for authenticity but not brand-consistent or theme-able out of the box; would need a "screenshot frame" component wrapper to make this repeatable
- Emotionally loaded rhetoric ("anti-white," "directional racism") is core to this specific video's virality — NOT a transferable format element, it's content-risk, don't copy the argument, only the proof-card structure
- No explicit subscribe/follow CTA — relies on shareability alone, works for an established creator with existing audience, likely underperforms for a new/unknown channel
